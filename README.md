# Диагностика автоматизации бизнес-процессов

Одностраничный сайт-опросник: помогает понять, имеет ли смысл автоматизировать процесс, достаточно ли обычного ПО или нужен ИИ, каков потенциальный эффект и риски.

**Принцип продукта:** ИИ — не самоцель. Рекомендуется самое простое и экономически оправданное решение.

## Стек

- React 18 + TypeScript (Vite)
- Чистый CSS (`src/styles.css`), без UI-библиотек
- Vitest для unit-тестов scoring-движка
- Backend, БД и внешние API не используются: все вычисления на клиенте, ответы никуда не отправляются

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # typecheck + production build
npm test         # unit-тесты scoring-движка
```

## Где логика диагностики

```
src/diagnosis/
├── types.ts      # доменные типы (вопрос, вариант, метрики, результат)
├── questions.ts  # конфигурация: 10 вопросов, варианты, веса, теги ответов
├── rules.ts      # пороги интерпретации, тексты рекомендаций, библиотека архитектуры
└── scoring.ts    # scoring engine: чистые функции, без React
```

Интерфейс (`src/components/`) ничего не знает о баллах — он получает готовый `DiagnosisResult`.

## Как менять модель

**Формулировка вопроса или варианта** — `src/diagnosis/questions.ts`:

```ts
{
  id: 'q3',
  title: 'Насколько процесс стандартизирован?',
  hint: 'Короткая подсказка под заголовком',
  options: [
    { id: 'q3-full', label: 'Полностью стандартизирован…', weights: { readiness: 3, ai: 0 }, traits: ['stable-rules'] },
  ],
}
```

- `weights` — вклад варианта в метрики `readiness` / `ai` / `business`. Максимумы считаются автоматически из конфигурации, поэтому правка весов не выводит оценку за диапазон 0–100.
- `traits` — поведенческие сигналы для гейта LLM, поиска противоречий и сборки архитектуры.
- `complexity` (вопрос 7) и `risk` (вопрос 8) задают сложность реализации и уровень риска.

**Пороги, подписи и тексты рекомендаций** — `src/diagnosis/rules.ts`: `BAND_THRESHOLDS`, `METRIC_PRESENTATION`, `RECOMMENDATIONS`, `ARCHITECTURE_LIBRARY`.

Компоненты UI при таких правках менять не нужно.

## Как формируется рекомендация

Комбинируются три оценки, гейт LLM, риск и сложность:

| Условие | Рекомендация |
|---|---|
| Business Value ниже 40 | E. Автоматизация необязательна |
| Низкая готовность + ИИ не обоснован | D. Сначала оптимизация процесса |
| Низкая готовность + ИИ обоснован | C. Частичная автоматизация с участием человека |
| Высокая готовность + ИИ обоснован | B. Гибридная автоматизация с ИИ |
| Высокая готовность без ИИ | A. Классическая автоматизация |

Гейт LLM не даёт рекомендовать модель только за «текстовые» данные: распознавание документов (OCR) и структурированные данные с правилами LLM не требуют. При высоком и критическом риске в результат всегда добавляется обязательное подтверждение человеком, а в архитектуру — аудит действий.
